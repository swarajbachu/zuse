# ACP integrations

Host-owned definitions live under the existing AppPaths.userData/acp directory. They use stable `acp-<uuid>` provider IDs; built-in IDs retain their existing wire values. Saved launch definitions expose environment variable names, with launch values held separately in credential storage. Credential bundles use the existing CredentialsService integration namespace. Each configuration revision references an immutable credential bundle, so a failed definition write cannot replace the previous launch credentials.

The server owns catalog retrieval, installation, persistence, connection probes, and authentication. The catalog is the official ACP registry with a bundled snapshot and a last-known-good disk cache. Distribution selection prefers the current platform binary, then npm, then uv. Package runners use pinned specs and host-managed caches. Binaries are downloaded into new installation directories and checked against supplied SHA-256 digests; extraction rejects escaping paths and non-regular tar entries. A candidate must pass ACP initialization/session creation (or report authentication required) before replacing the active definition. Old installations remain available to already-running processes.

`@zuse/acp/process` owns a bounded newline-delimited JSON-RPC process connection. `@zuse/agents/drivers/generic-acp` owns capability negotiation, provider session lifecycle, shared permission handlers, MCP gateway configuration, prompt submission, and translation. It uses the same ACP translator as built-in ACP drivers. Provider-specific compatibility switches remain limited to their existing tags; custom agents use the generic tag.

Model/mode discovery supports both legacy session models/modes and select configuration options. The model catalog exposes discovered modes as the `acpMode` option. Advertised commands appear in the slash-command menu, with existing Zuse client commands taking precedence. A probe waits at most 250 ms after session creation for the initial command notification.

A live session snapshots command, arguments, and environment. Resume requires advertised loadSession and never falls back to session/new after failure. A load response may omit sessionId; the saved cursor remains authoritative. Cancellation sends session/cancel and tears down an unresponsive process after five seconds. Terminal handles are scoped to their connection; retained output resolves ACP terminal content references into existing tool cards.

The renderer uses host-routed RPCs and keeps in-flight management operations in a host-keyed store. Settings controls use h-7. Removing a definition preserves conversations; attempting to reopen it reports that the provider is unavailable. Authentication uses existing login-link extraction and PTY surfaces; remote loopback OAuth remains dependent on the agent's supported authentication methods.

Validation: contracts/type checks, ACP process lifecycle tests, generic driver tests against the shared fake ACP fixture, translator regression tests, host-store/catalog tests, and browser setup checks. Refresh the bundled registry snapshot from https://cdn.agentclientprotocol.com/registry/v1/latest/registry.json and retain its upstream license.

Community adapters absent from the official registry are declared separately in `community-catalog.ts`, pinned and marked with their provenance. An upstream entry with the same ID takes precedence automatically. `BUILTIN_PROVIDER_CHOICES` controls new setup surfaces independently of persisted `PROVIDER_IDS`; Gemini remains readable for legacy conversations and is offered through ACP for new setup.

Hermes and OpenClaw are local harness presets in that catalog. Add them through Settings → ACP agents → Add. Their `local` distribution resolves an existing executable on the selected host instead of downloading a second installation. The catalog version is `host`: users maintain the native installation using its own upgrade flow. Credentials and configuration remain owned by the harness. Local presets use the same persisted definitions, model discovery, permission handling, cancellation, and resume path as other ACP agents.

- Hermes launches `hermes acp`. Install Hermes and its ACP extra, then configure the provider using `hermes model` (or `hermes acp --setup`) on the execution host. The preset sets `HERMES_ACP_SKIP_CONFIGURED_MCP=1` so globally configured MCP startup cannot block initialization; Zuse supplies its MCP gateway through the ACP session. Models come from Hermes' advertised inventory. See [Hermes ACP setup](https://hermes-agent.nousresearch.com/docs/user-guide/features/acp/).
- OpenClaw launches `openclaw acp` against the user's configured, running Gateway. Workspace execution, tools, model credentials, and MCP configuration belong to that Gateway, which may be remote; starting the bridge in a Zuse folder does not relocate the Gateway workspace. The preset persists `mcpEnabled: false` because OpenClaw rejects per-session MCP servers, including stdio servers. The generic driver sends an empty server list on both new and loaded sessions and does not launch the stdio MCP fallback. Zuse MCP tools are therefore unavailable through this bridge. See [OpenClaw ACP setup and limitations](https://docs.openclaw.ai/cli/acp).

`mcpEnabled` is optional in ACP definitions and launch snapshots; existing agents retain MCP injection by default. Save, duplicate, restart, and catalog installation preserve the setting. Custom bridge definitions can also set it through `provider.acp.save`.
