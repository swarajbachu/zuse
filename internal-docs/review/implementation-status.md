# Zuse Review implementation status

Updated 2026-10-07. This branch implements the hosted GitHub review MVP, with enrollment, private native authentication, dispatch, repository investigation, separate test compute, durable publication and billing integration. **Production admission and publication remain disabled.** Provider authorization, native inference confinement, real hosted staging and measured review quality have not passed their release gates. No live subscription inference, paid sandbox allocation, GitHub review publication or Polar export was performed during this implementation.

The branch was rebased onto `origin/main` at `b98c6db5`. The additive review migration is `0039_review_control_plane.sql`; it has been exercised in isolated PostgreSQL schemas, not applied to production. Existing cloud workspace runtime databases and recovery paths are unchanged.

## Implemented hosted path

- Setup reuses the user's verified GitHub connection and fresh repository permissions. GitHub connection alone neither enrolls repositories nor allocates compute. Personal/shared enrollment explicitly selects the native connection, model, worker placement, payer, runtime and optional monetary cap, with charge acknowledgement.
- PostgreSQL persists numeric GitHub identity, enrollment version, immutable run sponsorship/comparison, native connections, attempts, child activities, webhook inbox and publication outbox. Personal coverage is selected before readiness; a blocked personal connection cannot fall back to shared spending. Settings changes cannot reassign historical usage. Sponsor replacement requires disabling old coverage and explicit new-payer enrollment; there is no silent transfer.
- Signed webhooks are durably inserted before acknowledgement. Scheduled reconciliation coalesces updates for 30 seconds, capped at two minutes, rereads current PR/base state, deduplicates comparisons and fences stale refreshes. Manual reviews/reruns are explicit; enabling does not backfill. Forks need maintainer approval for the exact head SHA. Drafts and bots are manual-only.
- A dedicated E2B sandbox preserves one connection's native Claude auth home across pauses. The native process handles authentication; the control plane holds metadata and a one-use callback handoff, not subscription tokens. Payer/connection/verified provider identity leases serialize use. Reconnect, revocation, uncertain allocation, cancellation and restart have durable recovery paths.
- A clean worker image invokes the existing pinned native Claude SDK/binary. A root supervisor separates the native UID/auth home from a reader UID that exposes bounded immutable Git-object reads and the existing code index. Shell, arbitrary filesystem, browser, project configuration, plugins and user MCP tools are not exposed to the review agent. Local UID/process probes passed; the native model/tool confinement gate still requires live adversarial proof.
- `@zuse/review` retrieves repository facts, scripts, conventions, TS/JS symbols and relative imports from exact commits, then runs investigation and fresh-context verification. Trusted validation checks quotes, changed-line anchors, duplicate findings and coverage. The index ingests bounded batches with file/byte ceilings and immutable manifests. This is bounded repository understanding, not a complete call graph or a claim to understand every workflow.
- After native compute stops, a separate credential-free image performs paired merge-base/head checks using the same base-approved test/typecheck commands. Preparation accepts supported registry dependencies with frozen installs and lifecycle scripts disabled; test execution has denied network access. Results include command, per-side exit/status and bounded plain-text output. Unsupported setup, missing checks and timeouts are explicit. Test success is not a safe-to-merge score; test failures do not automatically create findings. See the exact supported setup envelope in [provider feasibility](provider-feasibility.md).
- All review and test allocations reserve through existing account cloud billing, share aggregate runtime/monetary limits, emit runtime observations and settle using provider evidence. Estimates and settled compute values include the billing period markup before plan allowances; they are not invoice charges. Conservative per-review caps include markup and shutdown margins. Login compute requires separate explicit consent. Delayed events map to immutable attempt/activity windows even when the native sandbox has been reused by another payer. Ambiguous windows remain unsettled rather than guessing a payer. Boxd is unavailable.
- Validated findings persist before publication. The control plane mints repository-scoped GitHub write credentials, posts commit-bound advisory checks and at most five inline findings, and includes remaining findings/check outcomes in bounded summaries. Publication has a separate disabled-by-default switch. Known pre-write failures may retry creation; ambiguous writes reconcile remote markers. Superseded results retain remote provenance. Publication retries do not allocate analysis compute.
- Compact settings/history show coverage, worker configuration and estimated versus settled costs. HTTPS/mobile landing and authenticated desktop/browser continuation carry only opaque finding IDs. Fix handoff rechecks access and current head, lets the requester choose their own workspace/account/payer, and stages explicit context without automatically starting an agent.

## Release gates and limits

1. Obtain provider authorization for paid hosted subscription reviews, including shared coverage and the exact native-login callback handoff. A successful login is not commercial approval. Claude has the initial implementation; Codex remains unavailable.
2. Publish the clean images, record immutable image/binary identities, and pass real native login/reconnect/account-match, pause/resume, hostile-repository/tool confinement, network, timeout and secret-canary tests on E2B.
3. Exercise one real PR through subscription execution, paired checks, GitHub publication, cancellation/new pushes, shutdown, provider evidence, ledger and Polar. Replay deliveries and lost responses. Local fakes and PostgreSQL tests do not establish this evidence.
4. Freeze and human-adjudicate the 50-defect/50-clean held-out corpus, then run matched diff-only/context/verifier comparisons. The implemented evaluation harness rejects missing adjudication and insufficient evidence. No corpus, precision/recall claim or competitor-parity claim is fabricated here. See [evaluation requirements](evaluations.md).

Launch defaults remain limits, not measured performance claims. Deep semantic/workflow resolution, broader language support, private package setup and arbitrary model-authored reproductions are beyond this MVP; [deep-review direction](deep-review-direction.md) distinguishes implemented behavior from those extensions.
