# Review quality release gate

External automatic posting requires a frozen, human-adjudicated evaluation corpus. No such corpus or measured quality claim ships with this change. Unit-test examples are synthetic and must not be relabeled as real reviews.

`@zuse/review` exports `validateEvaluationCorpus` and `evaluateReviewRelease`. Each case records repository, immutable buggy head SHA, development/held-out split, defect/clean label, adjudicator, provenance and high-severity defect count. Use distinct repositories across development and held-out splits. Freeze the manifest and record its content hash alongside engine, prompt, provider and model versions in each evaluation run. The metrics include numerator/denominator counts and nominal 95% Wilson intervals. Findings and PRs from the same repository may be correlated; report a repository-clustered analysis before interpreting these intervals as release confidence. Keep private repository content in authorized storage, not this documentation directory.

The gate requires at least 50 held-out defect PRs and 50 held-out clean PRs with human adjudication, one complete observation per held-out case, published-finding precision of at least 85%, clean-PR false-positive rate at most 10%, and high-severity defect recall of at least 60%. Missing denominators, missing reviews, incomplete runs, duplicate IDs, invalid counts and repository leakage fail closed. These are proposed launch thresholds, not measured product performance. Human labeling must identify distinct underlying defects so duplicate comments cannot inflate true-positive counts.

Run the same frozen cases through direct diff-only investigation, context investigation, and investigation plus fresh verification. Call `evaluateReviewRelease` separately for each variant; compare raw counts, precision/recall, p95 runtime and settled compute. A verifier that improves precision while removing important defects must be investigated before rollout. Exact model/provider identities must match for comparisons to be meaningful; subscription and API models are not presumed equivalent.

Operational fixtures separately exercise stale snapshots, duplicate deliveries, interrupted streams, provider refusal/quota failure, hostile instructions, malformed findings, invalid evidence, path traversal and cancellation. Passing behavioral fixtures does not satisfy the quality gate. Publishing remains gated until real human labels and observations exist.
